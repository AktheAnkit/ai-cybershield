# AI-Powered CyberShield — Weeks 1-6+ build

## What's included
- User registration/login with JWT stored in an httpOnly cookie
- SQLite database (Users, Scans) via SQLAlchemy
- Dashboard showing recent scans
- **Password Strength Analyzer** — uses `zxcvbn` (realistic crack-time estimation)
- **SSL Certificate Checker** — pure stdlib `ssl`/`socket`, checks expiry & protocol
- **Security Headers Checker** — checks for 6 standard security headers via `requests`
- **Website Security Scanner** — passive OSINT-style checks only (exposed
  `.env`/`.git`, cookie Secure/HttpOnly flags, server/framework version
  disclosure, robots.txt/security.txt presence). No port scanning or
  intrusive testing — deliberately stays within what any browser could
  already see, both for ethical/legal reasons and to keep scope realistic.
- **AI Phishing Detection** — XGBoost classifier trained on an augmented,
  20k+ row labeled URL dataset. Feature engineering + model comparison
  (Logistic Regression vs Random Forest vs XGBoost) is in `../research/`.
  Includes a documented fix for a real dataset bias (see
  `../research/README.md`) and a small trusted-domain allowlist.
- **⭐ AI Risk Score & Security Advisor** (core contribution) — runs SSL +
  Headers + Phishing together against one target, combines them into a
  single weighted 0-100 risk score via a deterministic rule engine, then
  asks a local LLM (Ollama) to turn the structured findings into a
  natural-language summary + top-3 prioritized actions. Falls back to a
  rule-based summary if Ollama isn't running, so the app never crashes
  from the LLM layer being unavailable.

- **PDF Reports** — every scan (and the combined AI Advisor assessment) can
  be downloaded as a PDF via ReportLab, from the dashboard's scan history
  or directly from the AI Advisor results page.

All 8 planned modules are complete. The one open item: the Website
Scanner's findings aren't currently folded into the AI Risk Score's
weighted formula — it remains a standalone tool. Adding it as a 4th
weighted component in `risk_rules.py` is noted as future work in the
paper.

## Setting up the AI Advisor's LLM layer (Ollama)

The advisor works without this — it just shows a rule-based summary
instead of an LLM-written one. To get the full AI-generated advisory:

1. Install Ollama: https://ollama.com/download
2. Pull a small model: `ollama pull llama3.2` (~2GB)
3. Ollama runs automatically as a local service on `http://localhost:11434`
   — no need to start it manually, `.env`'s `OLLAMA_BASE_URL` already
   points there by default.
4. Restart the FastAPI app and try `/tools/advisor` again — the page will
   say "Generated by llama3.2" instead of showing the fallback warning.

## Setup

```bash
cd cybershield
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

pip install -r requirements.txt
# If you're on Debian/Ubuntu and see an "externally-managed-environment" error:
# pip install -r requirements.txt --break-system-packages
#
# This installs everything needed for local development (SQLite by
# default). requirements-postgres.txt (psycopg2-binary) is NOT needed
# here — only install it if you're deploying with a PostgreSQL database.

copy .env.example .env          # Windows
cp .env.example .env            # macOS/Linux — then edit SECRET_KEY to something random
```

## Run

```bash
uvicorn app.main:app --reload
```

Visit http://127.0.0.1:8000 — register an account, then try the tools
from the dashboard: Password, SSL, Headers, Website Scanner, Phishing
Detector, and the AI Advisor (which runs SSL + Headers + Phishing
together and generates a combined risk score and recommendations).

## Deployment

A Render Blueprint (`render.yaml`) is included for one-step deployment
with a managed PostgreSQL database:

1. Push this repo to GitHub.
2. On render.com: **New +** → **Blueprint** → connect the repo. Render
   reads `render.yaml` and provisions both a web service and a database
   automatically — `SECRET_KEY` is auto-generated and `DATABASE_URL` is
   auto-linked, no manual copy-pasting needed.
3. Render's build command installs `requirements.txt` **and**
   `requirements-postgres.txt` (the Postgres driver, `psycopg2-binary`,
   which local SQLite development doesn't need — see Troubleshooting).

Two things to know about the deployed version: the free tier sleeps
after ~15 minutes of inactivity (first request after that takes
30-50 seconds to wake up), and Ollama won't be running there — the AI
Advisor will show its rule-based fallback summary instead of an
LLM-generated one. For a live demo of the full LLM-generated advisory,
run locally with Ollama installed (see above).

## Troubleshooting

**`ImportError: DLL load failed while importing ... An Application
Control policy has blocked this file`** (seen with scipy, pandas, or
other compiled dependencies) — this is a Windows security feature
(Smart App Control, or a Defender Application Control policy),
not a bug in this code. It blocks newly-downloaded compiled binary
extensions it doesn't yet trust, which numpy/scipy/pandas/xgboost all
ship. Fix: search Windows for **"Smart App Control"** and turn it off,
or add a scoped **Windows Defender exclusion** for just the `venv`
folder (Virus & threat protection → Manage settings → Exclusions → Add
a folder exclusion). A folder exclusion doesn't disable Defender
system-wide — it's standard, safe practice for any Python/Node
developer on Windows, not a security compromise.

**`pip install` fails trying to build a package from source** (meson/
Visual Studio Build Tools errors, e.g. for pandas, numpy, scipy, or
psycopg2-binary) — means pip couldn't find a prebuilt wheel for your
Python version and is trying to compile from source, which needs tools
most machines don't have. This project targets **Python 3.12** for
exactly this reason — very new Python versions (3.14+) often lack
prebuilt wheels for scientific/ML packages for months after release.
If you're on a newer Python and hit this, installing Python 3.12
alongside it (`py -3.12 -m venv venv`) is more reliable than chasing
individual package versions.

**`cp` / `copy` not recognized** — `cp` is Unix-only; use `copy` on
Windows CMD (both are shown in the Setup commands above).

## Notes for your viva
- Passwords are **never stored** — only the zxcvbn score/feedback is saved
  to the `scans` table (`analyze_password()` doesn't return the raw input).
- SSL check has no external API dependency (some online checkers rate-limit
  or go down) — it talks TLS directly, which also means it works if you
  demo on a machine without a browser open.
- Auth uses JWT (not just server sessions) because the same token model
  will let you expose a JSON API later (e.g., for a mobile client or for
  the AI Advisor module to call scans programmatically) without a rewrite.
